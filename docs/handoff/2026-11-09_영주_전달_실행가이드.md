## 2. 공법 법령 import (1번 파일)

### 2-1. 압축 풀기
`공법_LawImport_18개.zip`을 저장소 **밖** 폴더에 풉니다. 예: `C:\lawdata\public_import`
- 안에 `*.import.json` 18개와 `README.txt`가 있어야 합니다.
- `applicabilityStatus=VERIFIED`라서 **로컬 개발 DB에만** 넣어 주세요.

### 2-2. 서버 켜기 (순서 중요: Docker → Python → Spring)
import가 색인(임베딩)까지 하므로 Python 서버가 먼저 떠 있어야 합니다.

```powershell
# 창 1: Docker
cd C:\...\LawGround
docker compose up -d --wait
```

```powershell
# 창 2: Python (임베딩만 있으면 됨. 판정(Gemini)은 꺼도 됨)
cd C:\...\LawGround\ai-service
.\.venv\Scripts\Activate.ps1
foreach ($l in Get-Content ..\.env -Encoding UTF8) {
  if ($l -match '^\s*AI_SERVICE_API_KEY=(.*)$') { $env:INTERNAL_API_TOKEN = $Matches[1].Trim() }
}
$env:EMBED_BACKEND='bge-m3'; $env:RERANK_BACKEND='bge-reranker'; $env:VERIFY_BACKEND='off'
uvicorn app.main:app --host 127.0.0.1 --port 8001
```
`Application startup complete`가 나올 때까지 기다립니다(1~3분).

```powershell
# 창 3: Spring + import (local 프로필, 127.0.0.1 에서만 동작)
cd C:\...\LawGround\backend
.\gradlew.bat bootRun --args="--spring.profiles.active=local --lawground.law-import.dir=C:\lawdata\public_import"
```

### 2-3. 걸리는 시간과 확인
- 조문 2,155개를 임베딩하므로 **1시간 이상** 걸릴 수 있습니다(8GB·2코어 노트북 기준). Chrome·Discord 같은 앱은 트레이에서까지 종료해 두세요.
- 다시 실행해도 안전합니다. 같은 import는 재사용하고, 이미 색인된 조각은 건너뜁니다.
- 색인에 실패한 조각은 끝에 목록으로 나옵니다. 그 상태로 같은 명령을 한 번 더 돌리면 실패한 것만 다시 합니다.
- 다 끝나면 Spring을 Ctrl+C로 끄고, 다음부터는 `--lawground.law-import.dir` 없이 평소처럼 켭니다.

### 2-4. 과목별 LAW_IDS 값 얻기
`LAWGROUND_ANALYSIS_LIVE_LAW_IDS`는 DB `laws.id`(uuid)를 씁니다. import 후 아래로 확인합니다.

```powershell

```
공법 18개는 `source_law_id`(법령ID)로 구분합니다:

| 국토의 계획 및 이용에 관한 법률 | 009294 · 009419 · 009469 |
| 도시개발법 | 002024 · 003421 · 007096 |
| 도시 및 주거환경정비법 | 009410 · 009521 · 009524 |

현재 설정은 과목 하나(`LAWGROUND_ANALYSIS_LIVE_LAW_IDS`)라서 과목별로 나누는 작업이 필요합니다. 이름 제안: `LAWGROUND_ANALYSIS_LIVE_LAW_IDS_BROKER_LAW`, `LAWGROUND_ANALYSIS_LIVE_LAW_IDS_PUBLIC_LAW`.

### 2-5. 알아 둘 점
- **주택법(법률)은 '오늘 시행 중' 본문(시행 2026-09-08)**입니다. 같은 공포본의 2027-03-09 시행 예정본은 `effective_from`이 미래라 검색에서 빠지므로 넣지 않았습니다.

## 4. 선지 분석 태그 켜기 (3번)

지금 Spring `VerificationWire`는 `tagSetVersion != null`이면 `VERIFICATION_EXTENSION_UNSUPPORTED`, 태그가 있으면 `VERIFICATION_TAGS_UNSUPPORTED`로 거절합니다. 그래서 Python은 **기본으로 태그를 내지 않습니다.**

Spring에서 바꿀 것:
1. `tagSetVersion`: `null` 또는 `choice-tags-v1`만 허용
2. `tags[].code`: `TIMING` `CONDITION` `ACTOR` `CONCEPT` `NUMBER`만 허용. 선지당 최대 2개이고, `relation=CONTRADICTS` 선지에만 옵니다.
3. 화면 표시

| code | 표시 |
|---|---|
| `TIMING` | 시점·기한 |
| `CONDITION` | 조건 추가 |
| `ACTOR` | 주체·권한 |
| `CONCEPT` | 개념 오인 |
| `NUMBER` | 숫자·수치 오류 |

켜는 방법(Spring 수정이 배포된 뒤, **두 값을 같이** 바꿉니다. 한쪽만 바꾸면 `PROMPT_VERSION_MISMATCH`로 실패):
- Spring `.env`: `AI_VERIFIER_PROMPT_VERSION=verify-prompt-v2-tags`
- Python 실행 창: `$env:VERIFY_TAGS='1'` (기본 `0`)

## 5. 확장 기능 Python 경로 (4번)

계약 전체는 `docs/api/proposal-0.2.0-statement-and-similar.md`(맨 위 '구현 현황'), 스키마는 `ai-service/openapi-0.2.0-draft.yaml`입니다.

| 경로 | 하는 일 | 켜는 조건 | Spring 제한 시간(제안) |
|---|---|---|---|
| `POST /internal/v1/verify-statement` | 문장 하나 판정: `CONSISTENT / INCONSISTENT / HOLD`, 근거 인용, 틀린 구간, 고친 문장, 태그 | `VERIFY_BACKEND=gemini`(실제) 또는 `mock`(고정 응답) | 120초 |
| `POST /internal/v1/variation-diff` | 사용자 문장 vs Spring이 고른 기출 선지 1~5개: 바뀐 구간·태그·공부 팁 | 항상 켜짐(규칙 기반, 모델 불필요) | 5초 |

- 두 경로는 헤더 `X-Contract-Version: 0.2.0-draft`만 받습니다. 기존 경로는 `0.1.0-draft` 그대로입니다.
- Gemini 없이 Spring 개발하기: Python을 `$env:VERIFY_BACKEND='mock'`으로 켜면 `/verify-statement`가 계약에 맞는 고정 응답을 줍니다(`promptVersion=mock-statement-0`).

### 직접 불러 보기 (Python 창이 떠 있는 상태, 새 PowerShell 창)
```powershell
cd C:\...\LawGround\ai-service
foreach ($l in Get-Content ..\.env -Encoding UTF8) { if ($l -match '^\s*AI_SERVICE_API_KEY=(.*)$') { $tok = $Matches[1].Trim() } }
$rid = [guid]::NewGuid().ToString()
$h = @{ "X-Internal-Token" = $tok; "X-Request-Id" = $rid; "X-Contract-Version" = "0.2.0-draft" }
$body = @{
  requestId = $rid; subject = "PUBLIC_LAW"
  text  = "국토교통부장관은 기본계획에 대하여 5년마다 타당성을 검토하여야 한다."
  items = @(
    @{ itemId = "A"; truth = "TRUE";  text = "시장은 기본계획에 대하여 5년마다 타당성을 검토하여야 한다." },
    @{ itemId = "B"; truth = "FALSE"; text = "국토교통부장관은 기본계획에 대하여 3년마다 타당성을 검토하여야 한다." }
  )
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8001/internal/v1/variation-diff -Headers $h -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($body)) | ConvertTo-Json -Depth 6
```
A는 `ACTOR`(국토교통부장관은 ↔ 시장은), B는 `TIMING`(5년마다 ↔ 3년마다)이 나오고, 공부 팁이 함께 옵니다.

### Spring이 맡을 부분 (제안서 5절)
- `STATEMENT_CHECK` 작업: PREPARE → SEARCH(기존 검색 재사용) → VERIFY(`/verify-statement`) → SIMILAR → PERSIST
- SIMILAR: 기출 선지 은행(6절 파일)에서 **같은 근거 조문 + 임베딩 유사도**로 후보 3~5개를 고르고 `/variation-diff`에 넘깁니다. 실패해도 작업은 실패로 만들지 않습니다.
- 기존 5지선다 결과 화면의 선지별 "비슷한 기출" 버튼(같은 방식, 동기 호출)
- 기출이 보이는 화면 하단에 출처 표시(아래 8절)

## 6. 기출 선지 은행 (5번 파일)

`기출선지은행_3950.zip` 안:
- `bank-2026-11-09-<sha1 12자>.jsonl`: 한 줄에 선지 하나
- `manifest.json`: 버전, 개수, sha1, 제외한 문제, 출처 문구

한 줄 형식:
```json
{"itemId": "36-59-1", "subject": "PUBLIC_LAW", "exam": 36, "questionNumber": 59, "choiceNumber": 1,
 "stemHead": "…문제 머리말…", "text": "…선지 문장…", "truth": "TRUE|FALSE|UNKNOWN",
 "articles": [{"lawTitle": "도시 및 주거환경정비법", "articleLabel": "제4조"}]}
```
- 25~36회 2차 1교시(1과목·공법), 현행 법령으로 판단 가능한 문제만 넣었습니다.
- `truth`: 일반형은 문제의 '옳은/틀린'과 정답 번호로 계산합니다. 조합형(ㄱㄴㄷ)은 `UNKNOWN`이라 후보 순위 맨 뒤에 둡니다.
- 개수: TRUE 1,519 / FALSE 1,726 / UNKNOWN 705. 선지가 5개로 나뉘지 않은 12문제는 뺐습니다.
- `articles`는 문제 단위 정답 조문입니다(라벨은 AI 초안에 사람 표본 검수). `lawTitle`+`articleLabel`을 DB 조문과 이으면 "같은 근거 조문" 후보를 찾을 수 있습니다.
- 25~26회 등 옛 회차는 PDF 추출 띄어쓰기 잡음이 남아 있습니다. `/variation-diff`는 띄어쓰기·문장부호를 빼고 비교하므로 결과에는 영향이 작습니다.

## 7. 붙여넣기 시험 페이지 (6번)

`docs/prototypes/paste_split.html`을 더블클릭해 브라우저로 엽니다. 서버는 필요 없습니다.
- 붙여 넣으면 문제 번호를 떼고 지문과 선지 5개로 나눕니다. ①②③, 1. 2., 1) 2), (1) (2), 한 줄로 붙은 경우를 모두 처리하고, 줄이 끊긴 선지는 합칩니다.
- 문제 유형(옳은/옳지 않은)과 과목은 자동으로 고르고, 바꿀 수 있습니다.
- 정답 번호는 자동으로 고르지 않고(사용자가 책 정답표를 보고 선택), 회차·연도도 추측하지 않습니다. 기준일은 오늘이 기본값입니다.
- 결과는 `POST /api/v1/questions` 본문 JSON입니다. 앱으로 바로 보내지는 않습니다.
- 자체 검사: 개발자 도구 콘솔에서 `selfTest()` → `자체 검사 9개 모두 통과`

입력 화면에 넣을 때 참고할 부분: 분리 로직은 `split()`, `detectType()`, `detectSubject()` 세 함수(DOM과 분리)입니다.
